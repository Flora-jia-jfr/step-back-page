Which way next?

Do research agents know what each next step is worth?

Research agents act on their own estimates of what each next step is worth. We measure those estimates against what each step actually achieves, by running every option from the same decision point: analyze more, rethink the explanation, collect more of the same data, or run an experiment that tells explanations apart. In our first runs, Claude's estimates are ordered right but sized wrong.

  1. Q1Do its estimates match the real gains?Which step helps more, and by how much, relative to the price; too low or too high.
  2. Q2Where does the call break?In the estimate, in the choice, or in carrying the step out.
  3. Q3Is there room for judgment?Or do simple fixed policies already come close? Reported either way.
  4. Q4Can it be repaired?If it ranks well but misjudges size, does value calibration fix the choice?

Four kinds of next step

An analysis agent can do almost anything next. We group its open-ended actions by two questions: does the information come from the data at hand or from new data, and is the step meant to refine the current explanation or to test whether it is right?

Same first answer, four different right moves

An analyst asks whether a drug lowers blood pressure, using records from two hospitals, and must predict its effect in an older population. The working model is the same effect for every patient, after adjusting for severity. What should come next depends on what is actually true:

Motivation

Agents choose their next step by what they expect it to gain. Nobody has checked those expectations against what the step actually gains.

known
  • Research agents keep tuning when they should rethink (ResearchGym; "frame-lock" in AutoResearch), judged from traces afterwards.
  • Decision methods compare candidates by running them. LLM-IDEA runs every candidate experiment from the same data and reports regret; Outgrow a Theory learns when and how to revise a model class.
  • Information seeking goes wrong both ways: models stop asking before they have enough (MT-InfoSeek), and pay for checks that cannot change the decision (DIVA).
missing
  • In the decision methods, a fixed criterion or a learned policy makes the choice, and only one kind of step is compared.
  • Nobody has compared an LLM agent's own estimate of a step with what that step achieves from the same state, across different kinds of step.
  • So we cannot say when an agent underrates a step and when it overrates one.

Running every option from the same state is our measuring tool, the way a randomized trial is for a drug; it is not new by itself. Others use it to train a controller or to compare fixed criteria. We use it to score the agent's own estimate of each step: does it know which step helps more, by how much, does it act on that, and does it carry the step out?

Preliminary results

In one sentence: Claude's estimates of what new data would gain are ordered right but sized wrong. It knows roughly where data would help, but thinks they help several times less than they do, so it stops too early.

why the pilot needs a new toy

The switch box hides half of the switch settings. In all 12 tasks Claude pointed out that its records could not tell two explanations apart on that hidden half, but the task gave it no way to collect records there. So "test the explanation with a new kind of data" was impossible in this toy. The pilot's toy causal model (§05, Experiment setup) is built so that it is possible.

Goal and questions

The goal is to compare an agent's own estimate of each next step with what that step actually gains, against ground truth and counterfactual runs, and to find where the judgment breaks.

Experiment setup

The core design: at each decision point we save the agent's state, ask what each option would gain and which one it would take, and then run every option from the same save. Each option's realized gain is what its estimate is scored against. The pilot runs one agent (Claude Sonnet 5.5) on a small toy causal model built for this question.

terms used below
  • Window. One stretch of analysis: the agent reads the data, runs Python, and submits an answer.
  • Decision point. The moment right after it submits, when it could stop or take another step.
  • Discarded copy. A copy of the saved state where we ask questions; it is thrown away, so the questions cannot change later runs.
  • Branch. One option, run for real from the saved state.
  • Realized gain. Error before the step minus error after it, minus the price of any data bought.

The environment: a toy causal model

The model only generates the data; the agent's task is prediction, not causal discovery.

setup

Records from two sites: age A, a baseline score S, treated or not T, outcome Y. Predict the mean outcome with and without treatment in an older target population, as measured by a reference lab.

why causal
  • "More of the same data cannot settle it" holds by theory: unmeasured confounding and a real effect fit observational data equally well.
  • Each way of going wrong needs its own kind of evidence, so the remedies have clearly different values from state to state.
why build our own
  • We need look-alike truths, an exact ideal observer and all four remedies together.
  • BoxingGym has one fixed model per environment and no reanalysis action; ACED-Bench does not run remedies from one state.

A and R are prompts, not behaviors, so step 4 checks whether the stated working model or the code really changed. An option counts as best in a state only when it clearly beats the next one.

Stage 0 forks once, right after the first answer. Stage 1 also lets the agent follow its own choices and forks again at 2–3 later decision points along that path, to see whether its estimates keep up as a step's value changes.

Conditions and comparisons

prompt conditions
  • Neutral: goal, data and options only.
  • Generic review: "Check your analysis for omissions or errors."
  • Framework review: "Test the core assumptions of your model, consider alternative explanations, and consider what evidence could tell them apart."
  • None names a mechanism or says the model is wrong.
starting point
  • Main: the agent's own first window.
  • Ablation: it takes over a saved first window from another run or another model, since models treat others' errors differently from their own.
fixed-policy baselines
  • Always stop; always analyze k more rounds; always run the framework review; always buy diagnostic data.
  • Fit every candidate model at the start, then select.
  • A sequential model-class test, and a residual trigger.
  • All share the agent's analysis budget.
the repair: value calibration
  • Feedback: before deciding, the agent sees its past estimates next to the realized gains on a few practice states.
  • Outside rescaling: a monotone map from its estimates to realized gains, fitted on development seeds. It can fix the size, not the order, so it helps only if the ranking is good.
  • Tested on new seeds, at matched cost.

Do the four kinds cover what agents do?

trace-coding check
  • Why. The four kinds come from two questions, top down. This small check goes bottom up: it codes each step in real agent traces as A, R, D, X, stop, or "other".
  • Traces. Our 120 saved Claude analysis windows from the switch box, plus public traces of open-ended agents that can also request data or run experiments. Not the toy's traces: its menu is the four kinds by construction.
  • Report. The share of steps the four kinds cover, agreement between two coders, and what the "other" steps are. If many are "other", we change the kinds before building the application environment.

Scale and stopping rules

Stage 0 (about 300 analysis windows): 4 truths × 2 data sizes × 3 seeds = 24 states, with branches STOP, A, R, D and the three X options, one run each. Stage 1 (at most about 800) runs only if Stage 0 passes: more seeds, a second run of the main branches, controls, the prompt conditions, a start from another run's saved state, forks at later decision points, and the value-calibration repair on new seeds. The trace-coding check needs no new agent runs.
